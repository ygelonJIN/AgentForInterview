00 · 英文名、中文名与协议边界

先把流程图中的术语说清楚。这里的“SSE”“Prepare”“Classifier”“Route”分别属于 UI 事件序列化、LangGraph 节点、分类服务和条件边函数，不是四个同层级模型。

TERMS

Streamlit UI + SSE 消费 不是 Streamable HTTP

Streamlit Web UI + local SSE-style event consumer

中文：Streamlit 网页界面 + 本地 SSE 格式事件消费器。

  • EventQueue.to_sse() 只把 StreamEvent 序列化成 data: {json}\n\n 字符串。
  • process_streaming() 是 Python 异步生成器，直接把字符串 yield 给 UI，没有 HTTP Response、POST/GET endpoint 或网络 SSE 连接。
  • _run_streaming_impl() 在后台线程逐行解析 data: 后面的 JSON，然后更新 Streamlit 的正文和过程面板。
  • 因此它“使用 SSE 文本格式”，但不是协议意义上的 Streamable HTTP。
LLM/Graph → EventQueue → "data: {...}\n\n" ↓ Python async generator → Streamlit background thread → st.empty()

真正使用 Streamable HTTP 的是独立 MCP Server：run_mcp_server.py --transport streamable-http；它不在智能对话 UI 的请求链里。

LangGraph Prepare

node: prepare · implementation: LangGraphOrchestrator._prepare()

中文：本轮会话准备节点，也可以叫“会话上下文初始化”。

  • 由 graph.add_node("prepare", ...) 注册。
  • 由 build_thread_id(user_id, scene, session_id) 创建线程标识。
  • 调用 begin_turn()，把用户消息写入 ShortTermMemory。
  • 不调用大模型、不做 Intent 判断、不做 SQL/RAG。
START → prepare → classify

Unified Classifier

class: UnifiedClassifier · node: classify

中文：统一分类器，也叫“统一任务分诊器”。

它不只判断 Intent。它把过去分离的任务路由和意图识别合并为一次输出：

ClassificationResult { route, // react / plan_and_execute intent, // shopping / travel / customer_service / general sub_intent, // search / recommend / order_status / plan_trip / qa / chat ... retrieval, // sql_only / rag_only / mixed / none confidence, // 0.0 - 1.0 reason }

判断顺序是：关键词规则 → 上下文指代沿用 → 小模型 → 低置信主模型仲裁/格式修复 → 默认兜底。

LangGraph Route

conditional edge function: LangGraphOrchestrator._route(state)

中文：LangGraph 条件路由函数，或“顶层场景路由”。

它不是再次调用分类模型，而是读取 ClassificationResult，按固定优先级返回一个字符串边名：

intents 包含 shopping + travel → "shopping_travel" shopping → "shopping" customer_service → "customer_service" travel → "travel" general + react → "react" general + plan_and_execute → "general_plan" 其他 → "general"

复合意图条件最先判断；LangGraph 的条件边映射再把这些字符串连接到 ShoppingTravel、Shopping、Travel、CustomerService、GeneralPlan、ReAct、General 节点。

Intent 是怎么判断出来的？ Intent 不是 Route 之后再独立判断。它是 UnifiedClassifier 输出的字段；关键词层、上下文层或小模型层先决定 Intent，最后 _route() 只消费这个结果。分类后还有一层产品关键词安全网：如果 Intent=general，但消息含商品/价格/推荐词，会被强制改成 shopping/search/mixed。
